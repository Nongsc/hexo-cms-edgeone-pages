# 部署指南：EdgeOne Pages

本指南把 CMS 部署到腾讯云 EdgeOne Pages。整个应用由两部分组成：

- **前端静态资源**：`apps/web/dist`（Vite 构建产物）
- **Edge Functions**：`apps/api/dist-edge/index.js`（Hono API bundle）

两者由 `edgeone.json` 声明，部署在同一个 EdgeOne Pages 项目下。

---

## 一、前置条件

1. 一个腾讯云账号，并开通 [EdgeOne Pages](https://pages.edgeone.ai/)。
2. 一个 GitHub 账号，以及**存放本 CMS 代码的仓库**。
3. 一个用于 Hexo 博客的 GitHub 仓库（内容仓库，与代码仓库可以是同一个）。
4. 一个腾讯云 COS Bucket（图床）。

---

## 二、本地构建验证

在推送代码前，先在本地确认构建通过：

```bash
pnpm install
pnpm build
```

预期产物：

```
apps/web/dist/            # 前端静态资源
apps/api/dist-edge/       # Edge Functions bundle
    └── index.js
```

> `pnpm build` 会依次执行：
> 1. `@hexo-pro/core` 类型检查
> 2. `@hexo-pro/api` 类型检查
> 3. `@hexo-pro/api build:edge`（esbuild 打包 Edge Functions）
> 4. `@hexo-pro/web build`（vue-tsc + vite build）

---

## 三、推送代码并导入 EdgeOne Pages

1. 把本仓库推送到 GitHub。
2. 登录 [EdgeOne Pages 控制台](https://pages.edgeone.ai/)，创建项目，选择
   **Importing a Git Repository**，授权并选中本仓库。
3. EdgeOne 会读取仓库根目录的 `edgeone.json`，自动填充：
   - 构建命令：`pnpm install --no-frozen-lockfile && pnpm --filter @hexo-pro/web run build`
   - 输出目录：`apps/web/dist`
   - 函数目录：`apps/api/dist-edge`
4. 点击部署，等待构建完成。

> 如果 EdgeOne 未自动识别 `edgeone.json`，请在控制台手动填写上述三项，
> 并在「重写规则 / Routes」中增加：
> - `/api/(.*)` → `/apps/api/dist-edge/index.js`（Functions）
> - `/((?!api/).*)` → `/index.html`（SPA 回退）

---

## 四、配置环境变量

在 EdgeOne Pages 控制台的「项目设置 → 环境变量」中添加：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `CMS_ADMIN_USERNAME` | 是 | 管理员用户名，默认 `admin` |
| `CMS_ADMIN_PASSWORD` | 是 | 管理员密码，**务必修改** |
| `CMS_DB_PATH` | 否 | SQLite 文件路径，默认 `data/cms.sqlite` |
| `CMS_HEXO_VERSION` | 否 | 无法从仓库读取时展示的 Hexo 版本号 |

> **注意**：GitHub Token、COS 密钥等**不要**放在环境变量里，而是登录 CMS 后在
> 「系统管理 → 设置」中填写，它们会加密存放在 CMS 自己的 SQLite 中。

修改环境变量后需要重新部署才会生效。

---

## 五、绑定自定义域名（可选）

1. 在 EdgeOne Pages 控制台进入「域名管理 → 自定义域名」。
2. 添加域名并按提示配置 DNS CNAME 记录。
3. 可申请免费证书或使用托管证书开启 HTTPS。

---

## 六、博客仓库 CI 配置

CMS 本身不执行 Hexo 构建。点击「部署」按钮时，CMS 会调用 GitHub API
触发博客仓库的 `workflow_dispatch` 事件。

把 [`deploy/hexo-blog-deploy.yml`](../deploy/hexo-blog-deploy.yml)
复制到**博客仓库**的 `.github/workflows/deploy.yml`，然后按需在仓库
Settings → Secrets and variables → Actions 中配置：

| Secret | 用途 |
| --- | --- |
| `EDGEONE_API_TOKEN` | 用 CLI 发布到 EdgeOne Pages（可选，见下） |
| `EDGEONE_PROJECT_NAME` | EdgeOne Pages 项目名 |
| `CLOUDFLARE_API_TOKEN` | 发布到 Cloudflare Pages 时使用 |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare 账号 ID |
| `CLOUDFLARE_PROJECT_NAME` | Cloudflare Pages 项目名 |

### EdgeOne Pages 的两种接入方式

**方式一（推荐）**：在 EdgeOne Pages 控制台直接绑定博客仓库，
由 EdgeOne 自动执行 `hexo generate` 并发布 `public` 目录。
此时博客仓库的 workflow 只需负责构建，无需 `edgeone pages deploy` 步骤。

**方式二**：保留 workflow 中的 CLI 发布步骤，适合需要自定义构建逻辑的场景。

---

## 七、验证部署

1. 访问分配的域名（如 `https://your-project.edgeone.app`）。
2. 使用管理员账号登录。
3. 进入「系统管理 → 设置 → GitHub 关联仓库」填写并测试连接。
4. 点击「文章管理 → 从 GitHub 同步」导入已有内容。
5. 新建一篇文章，确认：
   - 列表中立即出现（SQLite 数据源）；
   - 博客仓库 `source/_posts/` 下出现对应 Markdown 文件（GitHub 双写）。

## 八、常见问题

### 1. 访问 `/api/*` 返回 404

检查 EdgeOne 控制台的路由规则是否包含 `/api/*` → Functions 的转发。
本地可通过 `curl http://127.0.0.1:8787/api/health` 验证 API 本身正常。

### 2. 登录后立刻退出

- 确认环境变量 `CMS_ADMIN_USERNAME` / `CMS_ADMIN_PASSWORD` 已设置；
- 浏览器 localStorage 中的 `cms-token` 属于内存会话，Edge Functions
  冷启动后会话会丢失，重新登录即可；
- 如需持久化会话，可把 `AuthService` 的 `sessions` Map 改为基于 SQLite 存储。

### 3. SQLite 数据丢失

Edge Functions 的文件系统在部分场景下不保证持久化。
如果需要跨部署保留数据，请：

- 方案 A：把 `data/cms.sqlite` 放到挂载的持久化卷（若平台支持）；
- 方案 B：把 SQLite 内容定期备份到 COS；
- 方案 C：将 Repository 层切换到平台提供的 KV / 数据库服务
  （接口已隔离在 `packages/core/src/repositories`，替换实现即可）。

### 4. 图片上传失败

- 检查 COS 配置是否正确（Bucket / Region / SecretId / SecretKey）；
- 确认 Bucket 的 CORS 设置允许你的域名；
- 确认所用密钥拥有 `PutObject`、`GetBucket`、`DeleteObject` 权限。

### 5. 构建时 `node:sqlite` 报错

确认 Node 版本 >= 22.5。EdgeOne Functions 的 Node runtime 已支持该内置模块，
`edgeone.json` 中无需额外配置。
