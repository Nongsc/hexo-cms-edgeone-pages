# 部署指南：EdgeOne Pages

本指南把 CMS 部署到腾讯云 EdgeOne Pages。整个应用由两部分组成：

- **前端静态资源**：`apps/web/dist`（Vite 构建产物）
- **Cloud Functions (Node.js)**：`cloud-functions/api/[[default]].js`（Hono API bundle）

两者由 `edgeone.json` 声明，部署在同一个 EdgeOne Pages 项目下。

> **为什么用 Cloud Functions 而不是 Edge Functions？**
> Edge Functions 是 V8 沙箱运行时，只提供标准 Web API（不支持 `node:sqlite`、
> 代码包 5MB、请求体 1MB、CPU 200ms）。CMS 需要 SQLite 持久化与完整 Node
> 生态，因此选用 Cloud Functions（Node.js v20，代码包 128MB、请求体 6MB、
> 最长 120s）。

---

## 一、前置条件

1. 一个腾讯云账号，并开通 [EdgeOne Pages](https://pages.edgeone.ai/)。
2. 一个 GitHub 账号，以及**存放本 CMS 代码的仓库**。
3. 一个用于 Hexo 博客的 GitHub 仓库（内容仓库，与代码仓库可以是同一个）。
4. 一个腾讯云 COS Bucket（图床 + CMS 数据库托管）。

---

## 二、本地构建验证

在推送代码前，先在本地确认构建通过：

```bash
pnpm install
pnpm --filter @hexo-pro/api build:edge
pnpm --filter @hexo-pro/web build
```

预期产物：

```
apps/web/dist/                     # 前端静态资源
cloud-functions/api/[[default]].js # Cloud Functions bundle（约 400KB）
```

---

## 三、推送到 Git 仓库

```bash
git init
git remote add origin https://github.com/<your-name>/<your-repo>.git
git add -A
git commit -m "feat: Hexo Pro CMS"
git push -u origin main
```

> **安全检查**：`.gitignore` 已排除 `apps/api/data/*.sqlite`（含 GitHub Token、
> COS 密钥、管理员密码）。推送前请用 `git status` 确认没有敏感文件。

---

## 四、导入 EdgeOne Pages

1. 登录 [EdgeOne Pages 控制台](https://pages.edgeone.ai/)，创建项目，选择
   **Importing a Git Repository**，授权并选中本仓库。
2. EdgeOne 读取根目录 `edgeone.json`，自动填充：

   | 配置项 | 值 |
   | --- | --- |
   | installCommand | `pnpm install --no-frozen-lockfile` |
   | buildCommand | `pnpm --filter @hexo-pro/api build:edge && pnpm --filter @hexo-pro/web build` |
   | outputDirectory | `apps/web/dist` |
   | nodeVersion | `22.11.0` |

3. 点击部署，等待构建完成。

> **注意**：`cloud-functions/` 是构建产物，已加入 `.gitignore`，
> 由 CI 的 `build:edge` 生成，**不要手动提交**。

---

## 五、配置环境变量

在 EdgeOne Pages 控制台「项目设置 → 环境变量」中添加：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `CMS_ADMIN_USERNAME` | 是 | 管理员用户名 |
| `CMS_ADMIN_PASSWORD` | 是 | 管理员密码，**务必修改** |
| `CMS_DB_PATH` | 否 | SQLite 路径，默认 `apps/api/data/cms.sqlite` |
| `CMS_DB_REMOTE` | 是 | **设为 `cos`**（启用数据库 COS 托管） |

> `CMS_DB_REMOTE=cos` 是必须的：Cloud Functions 的文件系统不保证长期持久，
> 启用后数据库文件会托管在 COS（键名 `cms/database/cms.sqlite`），
> 冷启动时自动恢复、请求结束后自动同步。

## 六、访问报 401：预览 URL 过期

若访问任何路径（含前端首页）都返回 **401**，且响应头包含：

```
X-EOP-MSG: eo_time missing
```

**这不是项目开启了访问控制**（EdgeOne Pages 项目设置中没有「访问控制」选项）。
这是 EdgeOne 的**预览域名时效限制**：

> 为确保内容合规，项目加速区域为「中国大陆可用区」或「全球可用区（含中国大陆）」时，
> 必须使用系统生成的预览 URL 访问，**链接有效期 3 小时**，超时返回 401。

解决办法：

| 方案 | 操作 | 适用场景 |
| --- | --- | --- |
| A（推荐） | 绑定自定义域名 | 长期使用，不受时效限制 |
| B | 控制台项目概览右上角「预览」按钮重新生成链接 | 临时测试 |
| C | 加速区域改为「全球可用区（不含中国大陆）」 | 仅海外用户 |

绑定自定义域名步骤：项目详情 → 域名管理 → 添加自定义域名 → 配置 DNS CNAME
→ 配置 HTTPS 证书（可申请免费证书）。

> 若加速区域含中国大陆，域名需先完成 ICP 备案。

---

## 七、首次配置

1. 访问分配的域名，使用管理员账号登录。
2. 进入「系统管理 → 设置 → GitHub 关联仓库」，填写 owner / repo / branch /
   Access Token，点击「测试连接」。
3. 进入「图片设置」，填写 COS 的 Bucket、Region、SecretId、SecretKey，
   点击「测试连接」。
4. 点击「文章管理 → 从 GitHub 同步」导入已有内容。

> 首次部署时 COS 上还没有数据库文件，CMS 会创建空库；
> 完成上述配置后，数据库会自动同步到 COS，后续部署不再丢失。

---

## 八、路由说明

| 路径 | 处理方 |
| --- | --- |
| `/api/*` | Cloud Functions（`cloud-functions/api/[[default]].js`） |
| `/assets/*` | 静态资源（长缓存） |
| 其他路径 | SPA 回退到 `/index.html`，交由 Vue Router |

> 静态资源优先级高于函数路由（EdgeOne 约定），因此 `/api/*` 下不要放置同名静态文件。

## 九、常见问题

### 1. `pnpm install` 失败（exit code 1，`ERR_PNPM_IGNORED_BUILDS`）

pnpm 10+ 默认禁止依赖的 postinstall 脚本并因此返回非零退出码。
`pnpm-workspace.yaml` 中已配置 `allowBuilds` 放行 `esbuild` /
`@parcel/watcher` / `vue-demi`。

> **注意**：该配置必须写在 `pnpm-workspace.yaml`，
> `.npmrc` 与 `package.json` 的 `pnpm` 字段在 pnpm 11 中均已不再读取。

### 2. `/api/*` 返回 404

- 确认 `edgeone.json` 的 `buildCommand` 包含 `build:edge`
  （否则 `cloud-functions/` 不会生成，CLI 会按纯静态项目处理）。
- 确认入口文件是 `cloud-functions/api/[[default]].js` 且导出了 `onRequest`。

### 3. 配置保存后刷新页面丢失

说明未启用数据库持久化。确认环境变量 `CMS_DB_REMOTE=cos` 已设置，
且 COS 凭据已配置（数据库需要 COS 才能托管）。

### 4. 数据库路径错误导致配置为空

`packages/core/src/db/sqlite.ts` 通过向上查找 `pnpm-workspace.yaml`
定位项目根目录（不依赖固定目录级数），因此 bundle 输出位置变化
（`apps/api/dist-edge` → `cloud-functions/api`）不会影响路径解析。
